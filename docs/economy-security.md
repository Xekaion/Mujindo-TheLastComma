# 무진도 거래 경제 보안·운영 기준

이 문서는 장비 경매장, 금괴-기억의 재 교환소, Steam Wallet 금괴 충전을
운영하기 위한 최소 보안 기준이다. 기능이 구현되어 있어도 아래 출시 게이트를
충족하기 전에는 실거래 모드를 켜지 않는다.

## 신뢰 경계

- 브라우저의 `localStorage`, 세이브 JSON, 장비 ID, 기억의 재 잔액, 결제 성공
  표시는 모두 신뢰하지 않는다.
- 기존 오프라인 세이브에서 만든 장비와 기억의 재는 `legacy_unverified`이며
  영구 거래 불가다.
- 거래 가능한 장비는 서버 CSPRNG 인스턴스 ID, 서버 발행 원인, 현재 소유자,
  변경 이력을 모두 가진 자산만 허용한다.
- 거래 가능한 기억의 재와 금괴는 서버 지갑과 append-only 원장에만 존재한다.
- 가격, 판매자, 구매자, 잔액, 아이템 옵션, 결제 상태는 클라이언트 입력을
  사용하지 않고 서버 레코드에서 다시 읽는다.

## 계정과 Steam 연동

- 모든 사용자는 변경되지 않는 내부 `account_id`를 가진다.
- Steam 클라이언트는 `GetAuthTicketForWebApi` 티켓을 보내고, 서버가
  `AuthenticateUserTicket`으로 검증한 SteamID64만 연결한다.
- 웹은 Steam OpenID 응답을 Steam에 다시 검증한 뒤 claimed ID의 SteamID64를
  사용한다.
- 거래 권한은 Steam 소유권 확인, 영구 라이선스, 계정 상태, 거래 잠금,
  활성 제재를 모두 통과해야 한다.
- Steam 소유권 검증 시각은 12시간까지만 유효하며, 만료되면 Steam 재인증 전까지
  거래와 계정 연동 PVP를 차단한다.
- SteamID는 계정을 식별하지만 사람 한 명을 증명하지 않는다. 기기·IP·결제
  신호는 위험도 판단에만 사용하고 단독 영구정지 근거로 삼지 않는다.
- Steam 비밀번호, 인증 티켓 원문, 카드 정보는 저장하거나 로그에 남기지 않는다.

## 경제 불변식

1. 사용 가능 잔액과 에스크로 잔액은 음수가 될 수 없다.
2. 장비 하나는 한 시점에 정확히 한 소유자 또는 한 에스크로에만 존재한다.
3. 판매 등록과 동시에 장비를 에스크로로 잠근다.
4. 구매자의 기억의 재 차감, 판매자 지급, 장비 소유권 이전, 매물 종료는 한
   DB 트랜잭션에서 전부 성공하거나 전부 실패한다.
5. 금괴 주문은 등록 순간 금괴 또는 기억의 재 전량을 에스크로에 예약한다.
6. 같은 매물의 동시 구매는 정확히 하나만 성공한다.
7. 모든 변경 요청은 작업별 멱등 키와 정규화 본문 해시를 가진다.
8. 같은 멱등 키와 다른 본문은 거절하고 위험 이벤트를 남긴다.
9. 원장과 감사 이벤트는 UPDATE/DELETE하지 않는다. 정정은 반대 방향 보정
   거래로만 처리한다.
10. 금액과 수량은 정수만 허용하고 서버 상한을 적용한다.

## 결제와 72시간 보류

- Steam판 금괴 충전은 Steam MicroTxn 서버 API만 사용한다.
- 서버 주문 생성 → Steam 승인 → 서버 `FinalizeTxn` 성공 → 원장 발행 순서를
  지킨다. 성공 화면 재방문이나 클라이언트 콜백만으로 지급하지 않는다.
- 결제 주문 ID와 공급자 거래 ID는 고유해야 하며, 재시도에도 한 번만 지급한다.
- 새로 충전한 금괴는 즉시 교환 가능 잔액으로 넣지 않는다. 원천별 gold lot에
  기록하고 최소 72시간이 지난 뒤에만 교환 가능 상태로 승격한다.
- `GetReport`를 지속적으로 대사하고 환불·차지백·사기의심환불이 확인되면 해당
  lot 회수, 부족분 채무 기록, 결제·거래 잠금, 연관 흐름 보존을 수행한다.
- 정상 거래 상대의 자산을 즉시 자동 몰수하지 않는다. 연관 계정은 지급 보류 후
  수동 조사한다.

## 위험 탐지

최소 위험 이벤트:

- 멱등 키 본문 불일치
- 잔액 부족·음수·오버플로 시도
- 알 수 없는 원산지 장비 업로드 시도
- 자기 거래 또는 연결 계정 간 거래
- 짧은 시간의 반복 등록·취소·매수
- 중간가에서 과도하게 벗어난 가격
- 동일 상대 집중, 순환 자금 이동, 즉시 재판매
- 신규 기기·신규 계정의 고액 주문
- 환불·차지백·사기의심환불
- 제재 회피로 의심되는 인증·자금 흐름

위험도 대응은 `관찰 → 추가 인증 → 지급 보류 → 거래 잠금 → 수동 심사` 순으로
강화한다. 단일 휴리스틱으로 영구정지하지 않는다.

## 즉시 제재 절차

1. 사건 번호와 근거를 만든다.
2. 계정 상태 또는 범위별 제재(`market`, `exchange`, `payment`, `login`, `pvp`)를
   서버에 기록한다.
3. `auth_version`을 올리고 기존 세션을 전부 폐기한다. PVP도
   `PVP_ACCOUNT_AUTH_ENABLED=true`인 운영 환경에서는 같은 내부 계정과 제재를
   매 동기화 요청마다 확인한다.
4. 활성 매물·주문을 취소해 정상 에스크로를 반환하거나 조사 보류 상태로 잠근다.
5. 거래·결제 API가 최종 커밋 직전 계정 상태를 다시 확인한다.
6. 요청 ID, 계정, 대상 자산, 원장 참조, 전후 해시, 운영자, 사유를 append-only
   감사 이벤트로 남긴다.
7. 영구정지 해제, 고액 보정, 대량 회수는 두 명의 승인을 요구한다.

Steam Game Ban은 멀티플레이 치팅 처분에만 사용한다. 결제 분쟁이나 경매장
어뷰징은 자체 거래·결제·로그인 제재로 처리한다.

## 출시 게이트

- [ ] Steam AppID와 최소 권한 Publisher Key를 Worker secret으로 설정
- [ ] Steam 티켓/OpenID 검증과 영구 소유권 확인 완료
- [ ] PvE 드랍·분해·강화·기억의 재 발행을 서버 권위 흐름으로 전환
- [ ] 과거 로컬 자산의 거래 불가 정책과 UI 표기 확인
- [ ] Steam MicroTxn Sandbox의 승인·거절·재시도·환불·차지백 훈련 완료
- [x] 웹 결제 복귀 시 `QueryTxn`으로 주문·계정·통화·상품·수량·금액·승인 상태
      검증 및 `Succeeded` 모호한 성공 복구
- [ ] `GetReport` 자동 대사, 환불·차지백 lot 회수, 부족분 채무와 계정 동결 워커
      완료 (`ECONOMY_PAYMENTS_ENABLED`는 그전까지 `false`)
- [ ] 72시간 금괴 보류와 정산 대사 작업 확인
- [ ] 동시 구매·취소·부분 체결·멱등성·IDOR·제재 경합 테스트 통과
- [ ] 원장 재생 합계와 지갑 materialized balance 전수 대조
- [ ] 운영자 MFA/RBAC/2인 승인과 침해 대응 연락망 준비
- [ ] 개인정보 보존 기간, Steam 정책, 출시 국가별 법률, 게임물 등급 변경 검토

한국에서 서비스한다면 현금 구매 재화와 플레이 획득 재화의 이용자 간 교환이
게임산업법상 환전·환전 알선 또는 사행성 판단에 해당하는지 출시 전에 전문
법률 검토와 등급분류 변경 검토를 반드시 거친다.
